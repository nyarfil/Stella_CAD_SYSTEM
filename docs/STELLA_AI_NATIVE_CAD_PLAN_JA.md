# Stella AI-native CAD 計画 (2026-10-18)

目的: Fusionアドイン(STEVE)に頼らず、**Claude Code経由**で「作る → 測る → 見る → 直す」を回せる、ローカル完結のCAD作業環境を作る。専用チャット画面は作らない。会話の入口はClaude Codeだけ。

## 1. 方針
1. 入口はClaude Code。道具はMCPツール、またはコマンドとして呼べる形にする。
2. 既存資産を先に使う。足りない部分だけ追加する。使い捨てスクリプトで済ませない（動いた処理は関数化し、検算に組み込む）。
3. OSSを積極的に使う。ただし導入前に名前・ライセンスをオーナーに見せる。GPL/AGPLはコードを取り込まない。
4. クラウド必須の道具は使わない。設計データを外に出さない。
5. Fusionは、オーナーが選んだ最終組立のときだけ使う。STEVEアドインは現状のまま凍結する（更新も廃止もしない）。
6. 未検証は合格と書かない。結果は画像と数値で報告する。

## 4. 段階計画
### 段階1: ビューア強化（最優先）
- three-cad-viewer を取り込み、STEPを面ID付きで表示する（OCPで面ごとに三角形化し、ID表を付ける）。
- 断面の蓋、寸法測定（点間・面間）、部品ごとの色・表示切替。
- 完了条件: 実際のマウスシェルSTEPで、断面と寸法が操作でき、画像が出る。

### 段階2: ビューアをClaude Codeの道具にする（2026-10-18 実装済み: `integration/stella-viewer/mcp_server.py`。画像はPlaywrightではなくヘッドレスEdgeで撮影。clearanceは step_distance で代替）
- 小さなMCPサーバー（stdio）を作り、`open`（表示更新）、`snapshot`（斜め・断面・比較の画像）、`measure`（距離・厚み・隙間）、`clearance` を提供する。
- 画像はPlaywrightでビューアを撮影する（見た目が画面と一致）。
- 完了条件: Claude Codeから1コマンドで画像と数値が返り、外出先でも確認できる。

### 段階3: 差分と品質の見える化
- 2つの版の重ね表示と差分ヒートマップ、厚みヒートマップ（見つからなかった機能のため自作）。
- 既存の検査ゲート（水密、最大厚み T+0.2 mm、質量）の結果を同じ画面で見られるようにする。

### 段階4: 測定付きの永続セッションへ寄せる
- build123d MCP と cadMCP の既存ツールを使い、各ステップで測定・検算し、結果をJSONで残す作法に統一する。
- 繰り返し使う処理は、新しいMCPツールとして追加する。

### 段階5: 画面からの指示
- ビューア上でクリックした面ID・座標・コメントを、Claude Codeが読めるキューに書く（スマホからも可）。
- 「この面を0.2 mm削って」のような指示を、面IDで正確に渡せるようにする。

### 段階6: スキャン→CADの自動化
- 現在のスキャンから薄い殻を作る流れ（PyMeshLab、CGAL、cadMCP）を、ツールとゲートで一回で再現できるようにする。
- 公開された手法は研究参考とし、取り込みは行わない。

### 段階7: Fusion依存の整理
- Fusionは最終組立のオプションにする。STEVEは凍結のままで、新しい版が出ても追わない。

## 5. 未検証・リスク
- three-cad-viewer の測定機能、yacvの断面機能は、READMEレベルでの推定。段階1の最初に実機で確認する。
- 面の永続IDには成熟したOSSが見つからない。OCCTの履歴（Modified）と幾何ハッシュで自作する。
- Playwrightのブラウザ本体は大きい（数百MB）。導入前に名前とサイズを見せる。
- 変換の速度は、9 MBのSTEPで約2秒（実測）。巨大なアセンブリは未測定。
- ビューアは127.0.0.1だけで動かす。スマホから見る場合は、外部公開せず、安全な経路（同一ネットワークのみ等）を別途決める。

## 6. 最初の一歩
段階1の着手。three-cad-viewer（MIT）をnpmから取り込み、実STEPで測定と断面を確認する。取り込み前に、名前・版・ライセンス・サイズをオーナーに見せる。
