# 任意基板・スキャンからの自作マウス設計契約

目標は任意の基板・形状を入力し、その実際のインターフェースから新しいマウスを設計すること。G305/ZS-F1は検証事例で、既定の穴位置・外形・機構として強制しない。未知の入力に対応する能力は、欠測箇所を特定して取得・設計へ進める能力も含む。入力のない寸法・仕様を生成して適合したことにしない。

## 入力形状の役割

| 入力 | 分かること | 別途必要なこと |
|---|---|---|
| 基板STEP/BRep | 保存された面、部品、穴、配置 | 実物版・単位・穴用途・搭載漏れ・電気仕様 |
| 基板のスキャン | 観測された表面 | 縮尺、遮蔽箇所、薄板厚、穴内面、センサー光学基準 |
| マウス外側のスキャン | 握り形状・外形の参考 | 内部空間・肉厚・基板位置・実際のクリック機構 |
| ケース内側のスキャン | 観測された受け・内壁 | 外側との登録、遮蔽部、締結、材料、製造公差 |
| 手のスキャン | 手の形と接触形状の参考 | 使用姿勢・握り方・操作中の接触・快適性 |

外側だけのスキャンから、見えていない内側の構造を観察済みとして扱わない。基板を複数使う設計では、主基板・入力基板等の役割と相互接続を個別に記録する。

## 共通座標への登録

1. 原形状を保持し、入力SHA、版、単位・縮尺の根拠を記録する。スキャナー出力の単位が不明なら既知寸法等で校正する。
2. 基板の支持面、部品側、センサー基準、取付穴、ホイール軸を測る。これらを部品名やソリッド列挙順だけで決めない。
3. 対応する非共線の3点等から剛体変換候補を求める。未使用の対応点・面で残差を確認する。3点への一致だけでは独立した登録精度を証明できない。
4. 縮尺校正と剛体配置は別記録にする。鏡映・非等方拡縮で保護基板を合わせない。片側の形状を他側へ鏡像コピーする前に実測する。
5. 最終的な机面・フィート・底ケース・基板・レンズの高さ連鎖を定義する。スキャンの最下点をセンサーの作動基準とみなさない。

登録の入出力: 入力SHA、校正値と出典、回転行列、平行移動、対応点/面、未使用検査点、残差、未知量。CAD面IDは入力ハッシュと工具に結び付け、別工具のIDへ直接転用しない。

## 任意ハードウェアへの設計

- 支持高さ、XY位置決め、締結保持、挿入・取り外し経路を分けて設計する。
- 任意のスイッチ配置に対し、指面から接触子への運動、復帰源、上下停止、反力経路を選ぶ。一体曲げ・独立曲げ・軸レバーを比較する。
- ホイールは回転軸とエンコーダーを合わせ、反対側支持と中央クリックの変位を別に扱う。参考G305の保持方式を別基板へ強制しない。
- センサーの型式に対応する光学距離とレンズ支持を固定する。外装都合で基板や光学基準を移動させない。
- 電源・配線・コネクタ・充電・アンテナ・スイッチ操作の空間を取る。外形スキャンだけでは電気仕様を決めない。
- 外装の内部空間は固定部品と動作包絡から設計する。スキャン全面を一定厚さオフセットするだけで自己交差・最小厚さ・組立が成立すると扱わない。

## CAD工具へ渡す内容

ホストは使用CAD MCPの現行工具とスキーマを読み、メッシュ参照、曲面編集、ソリッド化、ブール演算、履歴、測定の対応を確認する。未対応のスキャン変換は未対応として返し、メッシュを登録しただけで編集可能なShell Packへ昇格させない。

StellaCADでは対象案件に対応するBoard/Shell Packと保護形状を使う。別機種のready pack件数を対象基板の適合根拠にしない。FunctionBrief→設計根拠→型付きRecipe→CAD生成→検査の間で、未測定値と外部生成の来歴を維持する。

### 入力のreadyと設計への適用は別に確認する

- readyという保存状態だけでは、基板とシェルが同じ座標・版で組み合う証拠にならない。対象ペアの入力ハッシュ、配置変換、独立した照合形状を確認する。
- 部品の外形がSTEPに含まれていても、部品名・押下軸・作動量・復帰力・ホイール軸が確定したとは限らない。逆に、パックのswitchesが空でも、STEPから部品形状が欠落していると決めない。形状の存在と機能情報の充足を分ける。
- 間違った配置でも、薄い基板とケースの交差体積がゼロになる場合がある。無干渉に加えて支持面、穴、光学位置、コネクタ方向などの機能上の対応を確認する。
- 外接箱の最下点とケース最下点の差は幾何学上の差であり、メーカーが指定するセンサー光学距離ではない。レンズ、フィート、机面と指定基準を確認するまで光学成立は未評価にする。
- ボタン設計の不足が残っていても、配置を確認済みの固定支持など独立した設計工程は進められる。部分工程の成立を完成マウスの合格として扱わない。

## 汎用クリック計算工具

独立MCP: `mouse_library_click_window`。StellaCAD: `brain_mouse_knowledge_click_window(assessment=...)`。入力スキーマは `brain_mouse_knowledge_schema(name="click_window")` から取得する。

すべての入力はスイッチハウジングに対する共通プランジャ軸に正規化する。`g`は共通u=0での符号付き基準隙間、`u_rest`は押下・解放後の復帰状態での相対閉鎖量。gへ含めた寸法誤差をuへ重複して入れない。FP/OPの生座標を圧縮量へ換算せず混ぜない。

工具はON前停止、復帰後OFF、停止後の許容押込みを独立区間の極値で評価し、許される基準隙間の窓を返す。停止後の入力は指定設計荷重でのPCB・停止部・フレームの相対変形を含める。提案値は仮定として返し、資料の実在・版対応はホストが確認する。

欠測は条項ごとに未評価。既知の条項が満たされない場合は、それを欠測で隠さない。相関を無視した保守的条件が満たされないことは、実物の全組合せが必ず失敗する証明ではない。

許容最大押込みとOT最小保証は別で、前者の定義を必須にする。閾値区間の順序が保証できない場合は、仮定した単純区間モデルの成立を認定しない。全行程の戻り力、横荷重、反対ボタン、強度、疲労、調整保持はこの工具では計算しない。`physical_design_complete`は常にfalse。

工具の例: [仮想入力JSON](examples/generic_click_window_synthetic_input.json)、[計算結果JSON](examples/generic_click_window_synthetic_result.json)。全数値は算術確認用の提案値で、メーカーや実物の仕様ではない。押下に伴って圧縮が非減少となるモデルで余裕込み予算を評価し、確定した閾値逆転・運動包絡の逆転を区別する。調整前のgが窓から外れていても、設計窓自体が実現可能なら残す。

## 能力の確認条件

一般化できたという主張には、異なる配置・取付方式・スキャン品質の入力で、実際に登録・部品配置・外装と機構CADを生成し、干渉・動作・組立・製造を確認した証拠が必要。Generic board Alphaの数値テストは計算工具の確認に限り、任意基板・任意スキャンから完成マウスを作れた証明ではない。
