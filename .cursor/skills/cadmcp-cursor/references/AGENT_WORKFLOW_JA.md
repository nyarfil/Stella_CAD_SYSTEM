# CADエージェントの実行手順 — 構造知識を主役にする

## 役割と所有者

お客さんの目的・変更許可・材料・既存部品を保持して、ソリッド3Dを作る。cadMCPはマウス工場ではない。人間を操作したり、権限・実行枠を勝手に拡大する目的を持たない。実行回数と変更範囲は所有者が決める。複数役を演じたことと、独立したモデルや人間を実際に実行したことは区別する。

## 1. 入口

`brain_get`または`brain_open`で実原文と現在revisionを取得する。`brain_fs_status`で実データ量・CAD対応・意味索引を確認する。未導入ならインストール不足として報告し、デモを本番データの代わりにしない。意味索引が無いとき字句検索を成功扱いしない。Req2CAD検索は似た構造が役立つときの任意手順であり、必須ではない。

読み取れる寸法を再質問せず測る。必須で測れない値は未確定、試作選択値は提案とする。保護された既存部品は動かさない。

マウス（PCBとシェルがある案件）に限って、`brain_mouse_inspect_inputs` のあと Board Pack と Shell Pack を登録し、`brain_mouse_structure_gate` が両方 ready になるまでその案件の構造生成を開始しない。ディスク上の STEP はシェルパックではない。円柱面をねじ穴と認定しない。スキャンの中空化はこのサーバでは行わない。汎用の部品依頼ではマウスゲートを呼ばない。

## 2. 機能と実例を結び付ける（任意）

似た構造を探すときは `brain_studio_schema("FunctionBrief")`を取得し、元原文の該当箇所、機能、必要挙動、検索言い換え、幾何の前提を作る。同じ機能の言い換えは同じグループとし、別の必須機能を水増ししない。

`brain_fs_search_tasks`で検索する。候補UIDを`brain_fs_materialize`し、返された実PNG・STEP・面情報を読む。説明が「ガイド」でも中実の軸なら穴のある支持部には使わない。`brain_fs_interfaces`は円筒内面等を確認できるが、貫通、嵌合、荷重、寿命を証明するものではない。形状の欠損をLLMの創作で埋めて実例と称さない。

## 3. 構想を組み合わせる

`Matrix`に機能ごとの複数実現案を作る。各案に実STEP（Req2CAD UIDまたは登録済み project STEP）とevidence digest、使う面、採用する原理、変更点、力・反力の経路、組立方法、リスクを記入する。

`brain_studio_synthesize`で幾何前提と不適合を検査し、機能が揃う組み合わせを取得する。通った案が最も強いという意味ではない。候補ゼロなら前提・検索・機構を見直す。無関係な参照を添えるだけでゲートを通さない。

## 4. 実形状へ適合

`Recipe`へ部品・構築順・寸法の根拠・禁止事項・検査値を明示する。実STEPが必要（Req2CAD `reference` または登録済み `project_step`）。数字だけの箱はカタログの代わりにならない。モデル生成Pythonを無検査でexecしない。保護された既存部品はそのまま配置し、設計部品と混ぜて再生成しない。

`brain_studio_build`で実形状を生成する。全出力間の干渉、寸法、静止隙間、指定動作を検査する。レシピに書かなかった部品間も干渉検査対象となる。回転・弾性変形・公差ばらつき・疲労は直線移動検査で代用しない。生成PNGを視覚レビューし、STEPはカーネルで測る。STEPが正本。メッシュは表示用。

Fusionの `.f3d` に載せるときは `brain_fusion_handoff` が返したスクリプトだけを `fusion_mcp_execute` にそのまま渡す。Fusion Pythonを発明しない。印刷されたJSONを `brain_fusion_ingest` に返し、cadMCPが干渉・隙間を測り直す。見た目の成功では合格にしない。`.f3d` の保存はお客さんが明示したときだけ。

## 5. 討論を実行する

役割はrequirements、mechanism、assembly、manufacturing、verification。最初は別の実行コンテキストに同じ原文・参照CAD・形状・検査を渡す。初回結果が揃ってから、相手の具体的な指摘を2巡目に渡す。API/CLIがない場で実行済み討論を捏造しない。

指摘には対象、根拠、問題、具体的変更、必要再試験を含める。「賛成」「もっと強く」だけでは指摘にならない。多数決で欠陥や未検証を消さない。返答は実review/finding IDへ結び付ける。

修正時は原要求・保護部品・寸法検査・クリアランス・可動検査・未検証事項を固定する。通らない検査を消す、閾値を下げる、部品を出力から抜く行為で合格しない。修正後は新規attemptとして再構築・再レビューする。

## 6. 提出

提出するのは、変更理由、採用/却下の比較、実STEP/レシピ、実検査値、レビューの未解決点、製造・物理試験の残項目。試作を正本へ反映するかは所有者が決める。MCPの正常通信、テスト件数、モデルの自己採点を「最高品質の機械設計」の証拠にしない。
