# 自作マウス自動設計MCP — 調査・実装要件 v0.1

調査日：2026-09-16
状態：調査・設計提案。実装済みMCP、実機試験結果、成功率ベンチマークではない。

## 1. 結論と対象範囲

正本CADは n3r/AgentCAD。そこに専用の前処理・機構テンプレート・検査ライブラリを追加し、薄いMCPインターフェースから呼び出す。多数の汎用CAD MCPを併設するより、一つのCAD正本と一つのマウス専用設計エンジンを育てる。

対象は粘土外形をもとにした、既存PCB流用の3Dプリント用マウス機械部品。回路設計・ファームウェア設計は対象外。センサー、レンズ、電気スイッチ、エンコーダー等も原則として既存品を使い、光学部品まで印刷するという意味にはしない。

二つの独立した入口を用意する。

- 前処理：スキャンメッシュ＋単位・基準面＋肉厚・変換公差 → 検証済み中空シェルBRep。
- 主設計：検証済み中空シェル＋実装部品を含むPCB CAD＋部品仕様 → 印刷部品、組立モデル、検査記録。

既に中空ソリッドが得られている場合は、前処理を実行し直さない。ただし入力検査は省略しない。

## 2. 調査で確認した事実

### AgentCAD

確認版：`4b00aa503776eef9404bea9e489f3a244f423d3c`、2026-08-26。

- build123d/OpenCascadeによるBRep、参照STEP/BREP、アセンブリ、実行可能仕様、描画、変更履歴を持つ。STL参照はメッシュとして表示・計測する扱いであり、BRepブーリアンの対象ではない。[S01]
- `safe_shell`は失敗時に要求開口の一部だけを開ける経路、および縮小した内側形状を差し引く近似経路を持つ。曲面で等肉厚になる保証はない。作者のドーム試験の約20%薄化は一般的な誤差上限ではない。[S02]
- `smooth_loft`と`blend_surface`はロフト・面間接続用で、任意スキャンの自動分割・曲面復元一式ではない。直線補間や連続性低下へのフォールバックもある。[S03]
- ビルド失敗時に直前の正常形状を保持する。画面上の形状と最新ソースの成功を同一視しない。[S04]
- 通常CIのWindows portabilityは削除され、Linuxへの配備を対象とする記述がある。Windows向けの任意実行probeは残る。READMEのOS説明だけで判断しない。[S05]

### 他の既存要素

- Trimeshは読込、断面、接続成分、形状計測、単純修復等の基礎を提供する。任意の欠損や誤った形状を正しく復元する保証ではない。[S06]
- Open3Dの符号付き距離は、閉じたメッシュや交差しない形状という前提を持つ。壊れた入力に無条件適用しない。[S07]
- PCLは点群からB-splineを近似する実装例を持つが、初期化形状やデータ条件に依存する。マウス全体を一枚の曲面に自動変換できる証拠とはしない。[S08]
- 三角形を一枚ずつCAD面にするfaceted BRepと、滑らかなCAD曲面を復元することは別である。[S09]
- OpenCascadeのオフセットには自己交差等の制約がある。指定肉厚の内側形状が任意外形で必ず成立するわけではない。[S10]
- AI-CADには要求分解、再利用パターン、設計レビュー、修正・引継ぎの手順がある。CadQueryとbuild123dのコードはそのまま交換できる前提にしない。[S11]
- Casys-AI/mcp-dfmはSTEPから造形範囲、オーバーハング、サンプリング肉厚を測る。材料・装置固有の造形可否や支持材の除去可能性まで判定しない。[S12]
- Casys-AI/mcp-calculixは境界条件と材料値を明示する限定的な解析サービス。公開契約では一部品一体積が対象で、接触、複数材料、複数部品、複合材積層、大変形の汎用解析サービスではない。[S13]
- MeshLibは非商用・教育で無料のライセンスであり、商用まで無条件無料の必須依存には採用しない。[S14]

## 3. 推奨構成（以下は設計提案）

```text
Cursor / Codex
  ├─ AgentCAD MCP：正本CAD、描画、アセンブリ、履歴
  └─ mouse-engineering-mcp：専用操作・制約・検査の入口
       ├─ intake / scan2shell
       ├─ component_registry
       ├─ mechanical_templates / layout
       ├─ verification / manufacturing_checks
       ├─ optional_fea_adapter
       └─ artifacts / reports
```

専用モジュールはまず通常のPythonライブラリとCLIとしてテストし、MCPはその後で被せる。MCPで呼べることと、機械設計機能が実装されていることを混同しない。

幾何処理の第一候補はTrimesh、Open3D、NumPy/SciPy、build123d/OCP。PCLは曲面近似の比較用候補。複雑なメッシュ修復エンジンを追加する場合は精度・ライセンス・配布条件を別に評価する。

AgentCADと専用MCPが同じ部品を無制限に書き換えないよう、プロジェクト単位のロックと単一の書込経路を設ける。AI-CADは手順・レビューの参考とし、第二の正本を持たせない。

## 4. スキャンから中空BRepまで

1. 原本を読取専用で保存しSHA-256を記録。読込時の暗黙修復も作業コピー側に限定する。
2. 単位、実測長、前後、机面、利き手、欠損箇所を確定する。PCAは向きの候補に限り、勝手な鏡像化・スケーリングはしない。
3. 重複、退化、法線、境界、自己交差、接続成分を検査。意図的な底面開口とスキャン欠損を区別する。
4. 許容差の範囲で修復・平滑化。大きな欠損の推定補完は要確認として修復マスクに記録する。
5. 断面列または複数の曲面領域に分割し、B-spline曲線・曲面を近似する。単一ロフトで不足なら領域分割へ進む。
6. 曲面を接続し外形BRepを作る。元メッシュとの双方向偏差、断面、曲率、未評価領域を記録する。サンプル最大偏差を厳密な大域Hausdorff距離と呼ばない。
7. 指定開口を設けて内側にオフセットし、中空材質領域のソリッドを作る。
8. ソリッド妥当性、体積、開口、予期しない破片、肉厚分布、外形保存を検査。

**禁止する自動退避**：全体縮小による等肉厚の代用、肉厚の無承認変更、開口の削減、余分なソリッドの無断破棄、外形を太らせて干渉を隠す処置。

基準肉厚と最小肉厚を別項目にする。リブ・ボスの意図した増肉、縁・開口での計測定義を別管理する。オフセット失敗は、原因位置と候補対策を報告し、成功したふりをしない。

## 5. 部品パックに必要な情報

PCBの形状だけでなく、意味付きの機械インターフェースを登録する。

| 領域 | 必要情報 |
|---|---|
| 基板 | 実装状態の形状、取付穴軸・径、支持可能面、裏面部品、原点と姿勢 |
| センサー | レンズと光学開口、必要な取付基準面、机面までの設計距離と許容差 |
| 主スイッチ | 押す面・方向、作動点、許容押込み、仕様値の根拠 |
| サイドスイッチ | 基板固定基準、スイッチ位置、押込み方向、可動域 |
| ホイール | 回転軸、エンコーダ接続、ホイールクリック、必要な遊びと抜け止め |
| コネクタ・配線 | 挿抜空間、ケーブル経路、曲げ・組立時の空間 |
| 締結部品 | 使用ねじ、インサート等の型番、座面、工具経路 |
| 接地部 | ソール厚、貼付凹み、底板と机面の基準関係 |

未知値には `status: unverified`、根拠には型番・資料・実測日を付ける。一度登録した同じPCBは別スキャンでも再利用する。既知の位置を設計側が変更した場合は承認を取り直す。

## 6. 機構テンプレート

最初は検証しやすい分割構造を提案する：底板・内部シャーシ、外殻、分離主ボタン、サイドボタン、ホイール支持部。これは初期案であり、ユーザーが既に決定した構造を無断変更しない。

テンプレートは単なる完成形状ではなく、次を一体化する。

- パラメトリック生成関数。
- 適用範囲と不適用条件。
- 荷重経路、根元補強、ストッパー、組立順序の設計意図。
- 独立した寸法・干渉・可動・製造検査。
- 試作結果、失敗例、変更履歴。

初期対象は基板支持・ねじボス・リブ・シェル接合・主クリック・サイドボタン・ホイール支持・センサー窓・ケーブル出口。高性能をうたう未実測の薄肉ばね形状を自動採用しない。

参考候補のPloopy Mouseには製作ファイルと組立資料がある。ただしCERN-OHL-v2-Sで公開されており、設計ファイルを流用・再配布する際の条件を確認する。[S15]

## 7. 必須の検査と合否管理

| ID | 検査 | 判定条件の設計 |
|---|---|---|
| GEO-01 | BRep/出力妥当性 | 期待する部品数、材質体積、閉じた境界、エラーなし |
| REF-01 | 外形保存 | 許可された開口・切分け領域以外の偏差が承認公差内 |
| REF-02 | 参照位置保存 | PCB・光学系・スイッチ等の固定基準が変更されていない |
| WALL-01 | 基準肉厚・最小肉厚 | 曲率や局所部位に応じた追加計測。未完了の測線は未評価 |
| FIT-01 | 静的干渉・隙間 | 干渉量だけでなく必要隙間。意図した接触を別指定 |
| MOVE-01 | 可動域 | クリック・ホイール等の経路。離散検査の間隔と未保証範囲を記録 |
| CLICK-01 | クリック成立 | 作動点、押込み限界、接触面、ストッパー、復帰機構 |
| OPT-01 | センサー位置 | 実機仕様とソール等を含む寸法連鎖・最悪公差条件 |
| ASM-01 | 組立可能性 | 基板挿入、ねじ締め、工具経路、配線収納、分解順序 |
| PRINT-01 | 造形 | 指定装置・材料・方向・スライサー設定に対する評価 |
| PROV-01 | 版の一致 | 原本・要求・生成コード・成果物・検査が同じ版を参照 |

全項目を一つの加点スコアだけにしない。必須条件違反を軽量化等で相殺しない。

状態は最低限 `PASS / FAIL / UNVERIFIED / NOT_APPLICABLE` を分離する。NOT_APPLICABLEには理由を必要とし、未評価の言い換えにしない。草案出力は許しても、必須条件不明のものを検証済みリリースにしない。

形状の作者とは別の検証処理で実データを再計測する。ユーザー承認済みの要求を生成スクリプトが上書きできない構造にする。ファイル・パラメータ・要求・材料カード・プロファイル変更で関連結果を失効させる。

## 8. 製造とCAE

ユーザーの既知条件はQIDI Q2、0.4 mm、ABS Rapid。実際のプリンタ/フィラメント/工程プロファイル、造形方向、乾燥等の記録、嵌合試験片による補正値をプロジェクトに紐付ける。寸法補正や材料値は未確認の数字を初期正解として固定しない。

mcp-dfmは計測部品として再利用を検討するが、オーバーハングの机面接触領域、支持材を取り出せない形状、材料固有条件は専用側で扱う。肉厚はサンプル計測であり、大域最小の証明ではない。[S12]

mcp-calculixは一体部品の比較解析の候補。マウス全体の接触・ねじ締結・異方性・クリックばね・疲労をそのまま検証できると扱わない。必要な解析には別アダプターやモデル化を追加する。[S13]

ソルバー成功、解析条件下での合格、実物の合格は別状態。材料、荷重、固定場所、要素分割・収束の根拠がなければ強度判断を行わない。トポロジー最適化は後段で、ねじ座・基板支持・光学系・接触面を非設計領域として固定する。最適化出力も再度CAD化・製造検査する。

## 9. MCP公開インターフェース案

以下は提案名であり、現在存在するツール名ではない。

| ツール | 役割 |
|---|---|
| `inspect_inputs` | ファイル、単位、座標、欠落項目の確認 |
| `reconstruct_shell_surface` | スキャンに対する曲面候補作成と偏差報告 |
| `hollow_shell_strict` | 近似退避を許さない中空化 |

| `plan_mouse_assembly` | 部品分割・配置・依存順序の提案 |
| `generate_mouse_parts` | 選択テンプレートと許可パラメータからCAD生成 |
| `run_mouse_checks` | 固定仕様に対する独立計測 |
| `export_release` | 合否と版を確認して成果物を出力 |

ネイティブ幾何処理は上限付き子プロセスへ隔離し、タイムアウト・キャンセル・異常終了をJSONで返す。単なるプロセス分離をOS権限の隔離と呼ばない。モデルへの返却は大規模メッシュ本体ではなく、成果物ID・ハッシュ・測定値・断面画像等とする。

エラー例：`INPUT_UNIT_UNKNOWN`、`SCAN_REPAIR_REVIEW_REQUIRED`、`SURFACE_FIT_OUT_OF_TOLERANCE`、`OFFSET_SELF_INTERSECTION`、`DATUM_UNVERIFIED`、`CLEARANCE_FAILED`、`LATEST_BUILD_FAILED`、`STALE_REPORT`。不明値と異常終了を成功へ変換しない。

## 10. 実行環境と権限

Windowsホスト上で、LinuxバックエンドをWSL2またはコンテナで検証する案を優先する。ただしAgentCADの全機能がその構成で正常動作することは今回未実証。既に安定する環境があるなら先に保存・固定する。[S05]

初期試験はMCP接続、STEP読込、ブーリアン、描画、書出し・再読込、故意のカーネル失敗、権限制限。CADとメッシュ、解析サーバーは必要に応じて依存環境を分離し、無条件のlatest更新をしない。

CursorとCodexは公式のMCP接続方法に合わせて設定を用意する。利用クライアントとサーバー実装の対応版・プロトコルは実環境で確認する。[S16][S17]

入力ディレクトリは読取専用、作業/出力のみ書込可。ローカル接続を基本にし、LANへ無認証公開しない。任意Pythonを実行するCAD環境へ無関係な個人データやAPI鍵を渡さない。CAD計算のローカル実行と、Cursor/Codex側のクラウド処理は別であり、外部送信の対象となるコード・画像・寸法情報を確認する。

## 11. 実装順序と受け入れ試験

### M0：実行経路と入力契約

既知の単純ソリッドで接続・計測・出力・失敗検出を確認。原本不変、単位不明の停止、古い形状の出力拒否をテストする。

### M1：二つの小さい実証

A：実スキャン一件で外形保存と指定肉厚のBRep生成が成立するかを調べる。
B：既知の中空BRepと一種類のPCBで、正しい支持部と底板を生成する。

AとBは独立テストにし、曲面変換の不具合と内部機構設計の不具合を混同しない。

### M2：機能する一種類のマウス

シェル接合、主クリック、サイドボタン、ホイール支持、光学開口を順に追加。最終配置だけでなく組立経路・可動域を検査。全体を何度も印刷する前に機構単位の小型試験片を出力する。

### M3：他形状への再利用

同じPCBで別の外形、別の板厚へ展開。ノイズ、欠損、厳しい凹面、左右非対称、部品不足を含むテストセットを追加する。成功率、許容差、未評価率、介入回数、再生成可能性、所要計算資源を実測して適用範囲を定義する。

### M4：高度解析・最適化

実測材料カード、複数荷重、必要な非線形解析、寸法連鎖、軽量化、トポロジー最適化を追加する。解析モデルの妥当性を造形品で照合する。

## 12. 必要な実物資料と成果物

最初の実証に必要なのは、代表的なスキャン一件と使用PCB/実装部品のSTEP。中空化済みSTEPがある場合はそれも使う。併せて基準肉厚、外形の許容変化、前後・机面、主要部品の型番を確定する。スイッチ押込み等は部品パック登録で整理する。

完成システムの成果物：ソースリポジトリ、依存ロック、クライアント設定、Skill、入力スキーマ、機構テンプレート、正例/異常例テスト、STEP、STL/必要なら3MF、パラメータ、検査JSON、図・断面、BOM、組立手順、変更履歴。3MFやG-codeは選択スライサーに対応する別アダプターで扱い、MVPで無承認のプリンタ送信は行わない。

## 13. 今回の確認範囲

公開一次資料、公式ドキュメント、AgentCADの主要実装、AI-CADや外部MCPの公開契約を確認した。ユーザーの実スキャン/基板での幾何実行、MCP導入試験、Windows/WSLでの実行、全リポジトリのテスト、造形・組立・耐久試験は実施していない。したがって本書は成功率や寸法精度の保証ではなく、実装に進むための判断と検証計画である。
