# 自作マウス自動設計MCP：調査に基づく実装方針

調査日：2026-09-16
状態：**設計提案。MCPサーバー本体・実機接続・実物マウスの検証は未実施。**

## 1. 目的と境界

対象は、既存基板・部品を流用する3Dプリント製マウスの機械設計。PCBの回路・配線・新しい取り付け穴は設計しない。

入力経路は二つとする。

- `scan`：粘土外形のスキャンメッシュを前処理し、指定板厚のCADソリッドに変換する。
- `prepared_shell`：既に中空化されたSTEP/BREPを受け取り、検査後に同じ後工程へ入る。

中空ソリッド、登録済み基板パック、要求条件がそろった状態を機械設計の開始条件とする。MCPはModel Context Protocolを意味し、メッシュ変換アルゴリズムそのものではない。[S1]

## 2. 推奨構成

正本はn3r/AgentCADのプロジェクト、参照ファイル、パラメータ、生成スクリプト、固定仕様とする。STLやSTEPだけを正本にはしない。

```text
Cursor等の外部エージェント
  ├─ AgentCAD：既存のCAD操作・プロジェクト管理・描画
  └─ mouse-design-mcp：新規の用途別操作・実行監督
       ├─ geometry-worker：Open3D/trimesh、OpenVDB、必要時Manifold
       ├─ cad-worker：AgentCADと互換のbuild123d/OCP/OCCT
       ├─ validation-worker：幾何、可動域、組立、製造条件の検査
       └─ optional-cae-worker：Gmsh/CalculiX等、材料・境界条件を明示
```

上記は新規提案であり、これらの組み合わせがそのまま完成済みの配布物として存在するという意味ではない。まずCLIで再現できる処理を実装し、同じ入出力をMCPから呼ぶ。別々のCADソフトを多数常駐させることは初期要件にしない。

AgentCADの確認対象コミット：`4b00aa503776eef9404bea9e489f3a244f423d3c`。[S2]

### 既存コードから判明した必須対策

AgentCADの`safe_shell`には、正確なoffsetが失敗すると縮小した内部形状を引く近似への退避がある。要求された開口をすべて開けられず最大の一面だけを開ける退避もある。近似板厚・開口未達を成功として黙認しない。[S3]

AgentCADの現行CIは通常のWindows試験を外しており、Linuxでの実行を主眼に置いている。WindowsのCursorとLinuxバックエンドを接続する案を初期候補にするが、WSL2上の動作や隔離機能の実効性は別途実機検証する。[S4]

AI-CADのDFMA評価コードは独立したClaude CLI呼び出しを含む。Cursorのみの構成では、その経路を必須依存にしない。計画・レビュー・失敗記録の考え方を移植し、数値検査を外部LLM呼び出しから切り離す。[S5]

## 3. ソリッド化の達成水準

| 表現 | 用途 | 合格として扱う条件 |
|---|---|---|
| 閉じた三角形メッシュ | 造形と診断 | 印刷用メッシュの合格に限る。CADソリッド化達成とはしない |
| 三角面主体のBRep | 互換性確認、限定的な後加工 | 有効なソリッドであっても編集性・面数・処理時間を別評価 |
| 曲面フィッティングしたBRep | 本命の機械設計入力 | 外形偏差、板厚、開口、連結性、カーネル妥当性が規定を満たす |

今回の最小要件は、後工程で使える有効なBRepソリッドである。少数の滑らかな面や特定CADの履歴までを必須と決めつけない。面数を制限したfaceted BRepで後工程の演算・編集が十分安定するなら採用可能だが、表現の種類と性能を明示する。曲面再構成は品質・演算安定性が必要な場合の本命経路とする。

build123dの高速STLインポートはFace参照であり、読み込みだけで編集可能なソリッドになるわけではない。STEP/BREPとSTL/3MFを混同しない。[S6]

## 4. スキャンから中空BRepまで

### 4.1 受け入れと前処理

単位、縮尺、前後上下、底面基準、意図的開口を明示する。変換前の原本は変更しない。法線、退化面、自己交差、境界、連結成分を検査し、補修前後の偏差を残す。大きな欠損や不明な底面を無条件に補間しない。

### 4.2 距離場による中空形状の基準

外側で正、内側で負の符号付き距離を`phi`、要求板厚を`t`としたとき、理想化した殻領域は`-t <= phi <= 0`で表せる。狭い突起等では内側領域が消え、局所的に充実材になる場合がある。法線方向の一様な対応面がどこでも成立するという保証とは区別する。

OpenVDBはメッシュから符号付き／符号なし距離場への変換を提供する。符号付き変換には閉じた表面が必要で、自己交差等への対応は欠損の意味を自動復元する能力を意味しない。[S7]

OpenVDBを採用する場合は、内側の距離場の有効帯域が少なくとも指定板厚の位置まで届くようにする。ボクセル間隔だけを誤差保証と呼ばず、抽出面の偏差と板厚を測る。再解像度化の上限とメモリ制限を設ける。

### 4.3 BRep化の二つの経路

まず、許容偏差内で面数を抑えた中空メッシュをfaceted BRep化し、基板支持部のBoolean・開口・輸出入を含む後工程で実用性を試す。三角面数の上限だけでなく、実際の処理時間と形状検査の成功を判定する。これで要件を満たせるなら、無理に全面NURBS化しない。

曲面再構成が必要な場合は以下を用いる。

初期対象は、マウス外形として連続した曲面で、底面を特定でき、大きな欠損がない形状とする。上面・左右側面・前後等の曲面領域を選び、境界条件と外形偏差制限の下でBスプライン面をフィットさせ、接続・トリム・閉鎖する。左右対称化は標準処理にしない。

PCLには点群からBスプライン面をフィットする実装があるが、公式例にも初期化や点群形状の前提があり、マウス全体を一つの呼び出しで閉じたCADソリッドにする処理ではない。[S8]

有効な外側BRepに対しOCCTのシェル処理を試す。失敗時は、適切な分割変更・許容範囲内の再フィット・内側距離面の曲面再構成を候補とし、再度板厚を検査する。OCCTのシェル演算にも自己交差処理等の制約があるため、別ライブラリへの変更だけで解決すると見なさない。[S9]

BRepを成立させられないときは`BREP_FIT_FAILED`とし、診断メッシュを添付する。要求がBRepである限り、STLができただけで工程完了にはしない。

## 5. Board Pack：基板を一度登録して再利用する

STEP内の形状と、それが果たす機能を分けて保存する。各レコードには根拠、単位、許容差、状態、参照ファイルのハッシュを付ける。

必要な情報は、既存取り付け穴と接触可能領域、センサー／レンズと接地面の基準、スイッチの押下点・方向・作動量・許容押し込み量、ホイールとエンコーダの軸・可動域、USBプラグ／配線／その他部品の占有領域である。

見つかった円筒穴をすべてねじ穴と認定しない。欠けた部品モデルは寸法根拠を持つ保守的な包絡形状で補うか、未評価として停止する。STEPファイルの名前やメタデータをコード実行指示として扱わない。

座標合わせは、明示的な変換行列、対応する基準点、または既知のスキャン治具によって行う。外形スキャンと基板の中心を一致させただけでは配置の意図は復元できない。位置合わせ後にセンサー・基板等の固定基準を凍結する。

## 6. マウス専用設計ライブラリ

最低限、底板・基板キャリア、ねじボスと根元補強、シェル接続、クリック部品と押し子、支持部／支点、ストッパー、ホイール保持と開口、サイドボタン、センサー開口、ケーブルやUSBの通路を扱う。

テンプレートはモデルだけではなく、寸法パラメータ、適用条件、荷重・変形の想定、印刷方向、検査関数、試験片、実物試験記録の組とする。

LLMはテンプレートの選択と許された範囲の設計案を提案する。CAD処理は幾何生成と計測を担当し、別の検証処理が採否を決める。見た目のレビューは補助であり、クリック機構の数値検査の代わりにしない。

主クリックで少なくとも検査すること：無荷重時の誤作動、必要作動点への到達、最大許容押し込み前のストッパー接触、途中の干渉、許可された接触の範囲、戻り構造、組立可能性。弾性部品を剛体回転だけで検査した場合は、その検証範囲を明示する。

## 7. 用途別MCP API案

以下のツール名は新規提案であり、既存AgentCADにそのまま存在する名称ではない。共通して`project_id`、`revision_id`、`request_id`を扱い、巨大なメッシュ配列ではなくアーティファクト参照を返す。[S1]

| ツール | 主入力 | 主出力 |
|---|---|---|
| `inspect_inputs` | 入力ファイル参照、単位情報 | 欠損・形状型・参照不足・対応可能性 |
| `prepare_scan` | スキャン参照、許可した補修条件 | 修復済みメッシュ、変換、偏差レポート |
| `build_shell_brep` | 前処理済み形状、板厚、許容偏差 | BRep、板厚検査、近似／失敗履歴 |
| `register_board_pack` | STEPと機能メタデータ | 再利用可能な基板パック |
| `solve_layout` | シェル、基板パック、配置制約 | 配置案、制約充足／不成立理由 |
| `freeze_layout` | 承認された配置 | 不変な配置リビジョン |
| `generate_structure` | 配置、構造テンプレート、製造条件 | 底板・支持部・接続部 |
| `generate_actuation` | スイッチ／ホイール情報、機構テンプレート | クリック部・サイドボタン・可動部 |
| `validate_design` | 候補リビジョン、固定仕様 | 幾何・可動域・組立・製造の個別判定 |
| `render_inspection` | 検査項目と候補 | 断面、透視、寸法／偏差表示 |
| `export_candidate` | デジタル検査済みリビジョン | STEP/BREP、STL/3MF、検査記録 |

長い処理にはアプリケーション側の明示的なジョブ照会・キャンセルを用意し、クライアントが未対応のプロトコル機能を前提にしない。接続時に実際に対応するMCP版・能力を確かめる。

## 8. 合否、精度、安全性

検査結果は`PASS`、`FAIL`、`UNVERIFIED`を区別する。実行成功と設計合格を別フィールドにする。物理試験の状態も別に持つ。未検査項目、古いビルド、材料値の代用、形状未参加を合格に含めない。

判定は、外形・板厚・部品配置・穴位置・可動域・組立経路・製造条件それぞれに設ける。重大な不合格を総合点で相殺しない。検査しきい値を設計エージェントが自分で緩める経路を与えない。

全体の板厚サンプリングと、ボス根元・ヒンジ・溝端などの局所断面検査を併用する。サンプル最小値を数学的な大域最小値とは呼ばない。離散的な姿勢チェックだけで連続動作全域の衝突不存在を保証したことにしない。

原データ精度、曲面フィット誤差、距離場離散化、STLの近似、印刷ばらつき、組立ばらつきを別々に管理する。根拠なく統計独立と仮定して誤差を縮小しない。

部品を収めるためにシェルを削る場合も、固定外形と最小板厚の制約を必ず再検査する。不成立なら許された可変部だけを調整し、それでも解けなければ`INFEASIBLE_PACKAGING`を返す。

ワーカーはプロジェクト専用領域、入力の読み取り専用化、ネットワーク制限、CPU/RAM/実行時間制限を持たせる。コンテナ起動だけをもって必要な隔離がすべて有効とは断定しない。

## 9. 製造・検証計画

初期製造プロファイルは既存のQIDI Q2・0.4mm・ABS Rapidの条件を候補にする。ノズル幅の固定倍数だけで板厚合格を決めず、実際のスライスで残る壁、支持部の積層方向、サポート接触面、穴・嵌合の実測補正を確認する。

CAD形状のみ、数値解析済み、試作組立済み、耐久試験済みを別の達成状態とする。FEMは、根拠ある材料値・荷重・拘束・メッシュ収束をそろえた上で比較に使う。層間剥離、摩耗、戻り、クリック感、疲労寿命は必要な物理試験を省略しない。

テストデータは解析形状、既知の正常メッシュ、意図的な欠陥メッシュ、公開マウス設計、代表実スキャンに分ける。原寸だけでなく単位違い・反転・欠損・薄い突起・不可能な基板配置・古い検査結果の混入も試す。公開モデルの再配布条件は個別に確認する。

## 10. 実装段階と完了条件

| 段階 | 内容 | 完了条件 |
|---|---|---|
| A：基盤と技術試作 | AgentCAD接続、入力検査、代表スキャンのBRep化検討 | 同じ入力・版・設定から形状と検査を再現し、失敗を正しく通知 |
| B：固定構造 | 1種類のBoard Pack、ソリッドシェル、底板と支持部 | 実部品を無理なく取り付けられる試作。まだ完成マウスと呼ばない |
| C：機能試作 | 必要なクリック・ホイール・サイドボタン・開口 | 作動量、干渉、戻り、組立、印刷を含む動作確認 |
| D：対象拡張 | 複数スキャン、別基板、機構追加、CAE改善 | 未調整データで評価し、対応範囲と失敗率を報告 |

固定構造の試作とスキャン変換の技術試作は並行して進められる。どちらも独立に合格してから統合する。人日や期限は実データを処理していない段階では確定しない。

## 11. 任意依存の扱い

ManifoldはメッシュBooleanの候補。ただし入力の非マニフォールドをすべて自動修復するライブラリではない。[S10]

CGALのPolygon Mesh Processingは修復等の広い機能を持つが、確認したパッケージのライセンスはGPL。MeshLibも技術的候補だが、現行条件では非商用無料と商用契約を区別する。配布・企業利用の条件を確定するまでは必須依存にしない。[S11][S12]

## 12. 次に必要な実入力

代表スキャン1点と、対象基板・搭載部品・ホイール・光学部品等のSTEP一式を選定する。欠けた形状や仕様は不足項目表に残す。板厚、保持したい外形、クリック分割、ねじ類の方針を固定し、最初のBoard Packとテストケースにする。
