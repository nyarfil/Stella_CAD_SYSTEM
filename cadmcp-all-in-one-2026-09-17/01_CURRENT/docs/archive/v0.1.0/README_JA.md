# cadMCP Design Brain — v0.1.0

**雑な要求を、根拠のある設計意図 → 機能・挙動 → 構造案 → CAD作業契約 → 検証へつなぐMCPです。**

既存のAgentCAD・AI-CAD・Fusion等を置き換える製品ではありません。Cursor/Codexのモデルに設計を考えさせ、Python側が要求・参照・構造・作業順序・検証結果を管理する、独立して起動できる前段モジュールです。Python APIとして既存cadMCPに組み込むこともできます。

## まず動かす

Python 3.11以上が必要です。実行検証した環境はLinux/Python 3.13です。Windows向けスクリプトは同梱していますが、実際のWindows/Cursor画面での接続試験とは区別してください。

ZIPを展開し、そのフォルダをPowerShellで開いて実行します。

```powershell
.\setup.cmd --geometry
```

ローカル`.venv`へ本体・試験依存・CadQueryをインストールし、試験、環境診断、絶対パス入りMCP設定の生成を行います。初回インストールにはパッケージ取得用のインターネット接続が必要です。依存取得に失敗したら成功扱いせず停止します。CadQueryを入れない構成は`--geometry`を省略しますが、形状検証は使えません。

```powershell
.\.venv\Scripts\python.exe -m cadmcp_brain --workspace .\workspace demo --geometry
```

これは用意済みの設計IRを再生し、**2個の直方体試験片**を測定する動作確認です。実用マウス機構の完成データでも、LLMの自然言語理解ベンチマークでもありません。

導入の詳細とCursorへ渡す指示は **`INSTALL_INTEGRATE_JA.md`**。検証実績は **`TEST_REPORT_JA.md`**。

## 実装した部分

| 層 | 本リリースの実装 |
|---|---|
| 要求・意図 | 原文の引用、必須／禁止／希望、推測、未解決事項、単位、原文の未対応箇所の検出 |
| 構造検討 | 機能→期待挙動→機構→部品、2〜4案の比較、13種の初期構造パターン |
| 機械的整合 | 直押し方向の整合、復帰方法、ストッパー、ガイド、部品の接続、機能対応、部品数等の宣言検査 |
| CAD引き継ぎ | 型付きPlan、依存順、保護条件、寸法の出典、設計契約JSON／引継ぎMarkdown／設計グラフ |
| 計測 | STEPのB-rep有効性、ソリッド数、外接寸法、部品間最短距離、干渉体積。CadQuery/OpenCascadeを実行 |
| 状態管理 | SQLite、revision競合検出、原文追加で下流無効化、ファイルハッシュ、検証履歴 |
| 接続 | 17個のMCPツール、Python API、任意で有効化するAgentCAD HTTPアダプター |

本体は外部LLM APIを呼びません。**理解・発想・比較・CAD操作はホストのCursor/Codexモデルが担当**します。既存のホスト利用に伴う費用・制限は別です。ルールとMCPを追加しただけで、モデル能力やユーザー意図の正解率が保証されるわけではありません。

## 「勝手な解釈」をどこで止めるか

「サイドボタンを押しやすく、壊れにくく、複雑にしないで」という指示だけから、ボタンの移動量、寿命、板厚、作動力は確定させません。明示された目的は残し、数値がないものは未確定、試作の設計値はproposalとします。

実際のスイッチ押下方向が分かっていなければ、確定した構造計画に進めません。分かっている場合も、指の押す方向とスイッチの押される方向を別々に記録します。直押し案で両方向が食い違えばエラーになります。復帰をスイッチの内蔵ばねに任せる案には、摩擦に勝てるかという未検証の注意を残します。

**原文の文字列対応は意味理解の証明ではありません。** 大きな引用で対応漏れ検査をすり抜ける、原文を曲解する、必要な未確定事項を書き忘れる等はモデルのレビューが必要です。同梱Skillはここを明示的に検討させますが、認証された人間の承認機構ではありません。

## 成功と未検証を分ける

`geometry_status=pass`は列挙した形状検査への合格です。`overall=declared_checks_passed`も列挙項目への合格であり、要求や試験の十分性は保証しません。

`manual`、`physical_test`、`external_geometry`はこのリリースでは**常にunknown**です。例えば操作感、疲労寿命、実印刷の品質、未実装の壁厚測定をLLMの自己申告で合格にできません。試験未実施、STEP不足、古い契約のSTEP、測定器不在、カーネル失敗もunknownです。実測値が基準に違反した場合はfailです。

静的な2部品間距離は、動く全域の干渉、挿入経路、工具アクセス、拘束の妥当性を証明しません。部品は**同一アセンブリ座標系**でSTEP出力する必要があります。この座標意味は利用側が保証します。

## 本リリースに含まれないもの

任意の文章から全自動で正しいマウスを完成させる保証、スキャンメッシュからの自動ソリッド復元、汎用B-rep形状生成器、FEA／疲労／トポロジー最適化、実機の印刷・耐久試験、Req2CADのデータセット、iDesignGPT等の丸ごと組込みは含みません。これらを実装済みとは扱いません。

ユーザーの既存cadMCPソースコードは今回未取得のため、それに対するパッチ適用や実環境での統合完了も行っていません。既存コードを読んで統合するための手順・指示・APIを添付しています。

## 構成

```text
人間の原文
  ↓ Cursor/Codex + intent prompt
Brief ── 出典・単位・矛盾・推測の検査
  ↓ 機能／挙動 + パターン検索
Concepts ── 機構／部品／接続・選択可能性の検査
  ↓ 比較・選択
Plan ── 依存順／保護条件／寸法根拠／試験義務
  ↓ contract.json + CAD_HANDOFF.md
既存CADバックエンド（ホスト操作、または許可済みAgentCAD呼出し）
  ↓ STEPと契約ハッシュ
CadQuery/OpenCascade実測
  ↓
pass / fail / unknown とその根拠
```

プロンプト、パターン、状態モデル、検査コードは分離されています。上流のどの着想を採り、何を採らなかったかは`docs/UPSTREAM_AUDIT_JA.md`を参照してください。

## 運用上の境界

標準入出力のMCP **2025-06-18のtools/resources/promptsを実装した限定サーバー**です。公式MCP SDKは使用していません。現行仕様の全機能実装・公式クライアント相互接続認証は主張しません。HTTP公開、認証、sampling、elicitation、非同期task、購読は提供しません。同期処理中のcancel通知で処理を中断することはできません。測定子プロセス／HTTPにはタイムアウトがあります。

作業場所は信頼できるユーザー専用ディレクトリを使ってください。SQLiteとハッシュはうっかりした改変・競合検出のためで、悪意ある同一OSユーザーに対する改竄防止基盤ではありません。STEP測定子プロセスもOSのセキュリティサンドボックスではありません。

別MCPとして並べるだけでは、ホストが既存CADへ直接書き込むことを禁止できません。**強制ゲートが必要なら既存cadMCPの書込み入口に組み込みます。** AgentCADブリッジも、許可されたツール引数が設計を意味的に正しく実現することまでは証明しません。
