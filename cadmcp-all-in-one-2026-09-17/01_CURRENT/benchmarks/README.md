# 独立した成果物の受入検査

生成モデルのRecipeや自己申告ではなく、出力STEPを再読込して固定条件を検査する。
`studio/acceptance.py` が公開入口。元要求、部品数、配置込み外接範囲、体積、必要領域・禁止領域の体積占有を評価する。
同じCadQuery/OCCTを使う別経路の検査であり、別カーネル検証や物理性能の証明ではない。

## 評価者向けの手順

1. 生成前に要求と受入JSONを作成し、SHA256・日時・評価対象版を保存する。JSONを生成モデルに書き換えさせない。
2. モデル、呼出し数、タイムアウト、使用工具、人間介入、検索データを固定して実行する。
3. 新しい検査プロセスから `python -m cadmcp_brain.studio.acceptance --spec <JSON> --spec-sha256 <固定値> --step <成果物STEP> --report <新規報告JSON>` を呼ぶ。
4. 終了0は「この幾何条件に合格」、1は不合格、2は検査未完了。2を合格や対象除外へ変えない。
5. 同じ条件を比較対象にも適用する。失敗試行を含む全試行数、実行時間、モデル利用量、人間介入を集計する。

検査時のハッシュ一致だけでは「生成前から仕様が固定されていた」ことを証明できない。
生成開始前の履歴や第三者の保管記録を別途残す。署名・所有者の真正性をこのCLIが保証するわけではない。
CLIは既存report、STEP、specの上書きを拒否する。既定タイムアウト60秒、最大300秒。

`development/` は開発中に内容が知られている公開例。これだけで他製品より優秀と結論付けない。
未見案件・提供CADの編集・自由曲面・機構・要求変更・保護部品・例外復帰は別に評価する。
実機の押し心地・摩擦・疲労・製造ばらつきは実物の試験が必要。

外部参考（2026-09-20確認。実行・投稿していない）:

- [CADGenBench](https://github.com/huggingface/cadgenbench): STEP主体で生成・編集を評価し、validity、形状、interface、topologyを分ける。
- [Multi-Agent-CAD](https://github.com/Pan-Chera/Multi-Agent-CAD): 多段の設計・検証と計算予算を明示した比較の参考。
- [AgentCAD](https://github.com/n3r/AgentCAD): parametricな編集性、実カーネル検査、エラーを使う修正経路の比較対象候補。

他システムの説明は自己公表内容であり、cadMCPとの優劣を証明しない。ランキングへの提出、外部へのCAD送信、公開は所有者の別途承認が必要。
